# Milestone 06.6 — Login hardening

## Goal

Make the public login surface resilient against the drive-by credential scanners that hit any telnet listener on the open internet. Three coordinated defences share a single in-process service:

1. A DB-backed list of forbidden usernames, seeded with the SecLists shortlist of bot-favoured names (`root`, `admin`, `ubnt`, …). A login attempt that uses one of these names disconnects immediately *and* flags the source IP. Account create / username rename attempts that hit the list are rejected with a clear error.
2. An in-process IP deny list with two row classes — temporary (TTL, default 5 min) and permanent — checked at TCP accept time before any byte is read from the connection.
3. An optional UDP emitter that announces flagged IPs to a separately deployed [`subtext-filter`](https://github.com/vaelen/subtext-filter) bridge, which installs an `nft drop` rule on the upstream router.

A second trigger flags an IP the same way: too many failed-password attempts from one source within a configurable window (default 5 in 60 s). Admins manage both lists from `@`-commands, the M6.4 admin menu, and Lua. M6.6 also ships the `@rename` admin command, because the spec requires rename to honour the disallowed list and rename does not exist yet.

## Dependencies

- M1 (telnet + TLS listeners, `acceptLoop`).
- M2 (`internal/auth.Store`, account creation, password hashing).
- M6.4 (admin menu state machine, `@`-command dispatcher, `adminAudit`).

## Scope

### Disallowed usernames

- New `disallowed_usernames` table; case-insensitive (mirrors `accounts.username COLLATE NOCASE`).
- Seeded from the SecLists shortlist (~30 names): `root`, `admin`, `administrator`, `user`, `ubnt`, `guest`, `enable`, `supervisor`, `support`, `test`, `oracle`, `postgres`, `mysql`, `ftp`, `sysadmin`, `operator`, `mail`, `anonymous`, `pi`, `cisco`, `tomcat`, `nagios`, `info`, `service`, `sysop`, `default`, `system`, `manager`, `webmaster`, `nobody`.
- Login attempt with a disallowed name → drop the connection immediately and flag the IP. No password prompt is rendered.
- Account-create / rename attempts (self or admin) that hit the list → reject with `ErrUsernameDisallowed` and a user-facing error message. No IP flag — legitimate user typo.
- Admin adding a name that matches an existing `accounts.username` → refuse with error. Admin must rename or delete the account first.
- The keyword `new` (the account-create sentinel in `internal/session/login.go:34`) cannot be added to the list.

### IP deny list

- One `ip_denials` table; `expires_at` is `NULL` for permanent rows and set to a future unix timestamp for temporary ones.
- All rows are mirrored in an in-memory cache keyed by `netip.Addr`. Hydrated from the DB on `Service.Start`; expired temporary rows are purged at startup.
- Pre-auth gate runs inside `acceptLoop` (telnet *and* TLS) **before** the per-connection goroutine spawns. The check is one read-locked map probe plus a `time.Now()` comparison, cheaper than the `wg.Add(1)` already on the hot path. Denied connections are `Close()`d with one `slog.Info("connection denied", ...)` line.
- Eviction is layered: lazy on every lookup (correctness between ticks), plus a ticker-based janitor (default 1 min) that drops expired rows from cache *and* DB, copying the files-janitor idiom at `cmd/wintermute/main.go:373-388`.
- Automatic temporary adds are themselves toggleable via `security.auto_deny_enabled` (default true). With it off, disallowed-username and failed-password attempts still drop the connection and still emit the structured log line, but no IP is ever inserted — the bot can reconnect, only to be dropped again on the next disallowed name.

### Failed-password flagging

- Per-IP attempt counter, in-memory only (no DB), sliding window.
- Defaults: 5 failed attempts in 60 s → flag. Both tunable.
- The bump lives in the session layer (`internal/session/login.go`), not in `auth.Store`. This guarantees it fires identically on the unknown-user and bad-password code paths, preserving the dummy-verify timing mitigation at `internal/auth/auth.go:171-175` and closing the username-existence oracle that an attempt-counter-in-auth would otherwise create.
- Each push trims entries older than the window, so memory stays bounded by the threshold count per active IP.

### UDP emit to subtext-filter

- Wire format verified against `subtext-filter/src/main.rs`: UDP, single packet, payload = IPv4 dotted-quad ASCII, **no newline, no auth, no reason field**. The listener has a fixed server-side 5-minute TTL, renewed by re-sending the same IP.
- Toggleable (`security.filter.enabled`, default off — most operators won't deploy subtext-filter). Single config field `security.filter.address` defaulting to `127.0.0.1:1234`, validated at config load via `net.ResolveUDPAddr("udp4", addr)`.
- IPv6 source addresses: skip the UDP emit (subtext-filter's bridge filter is IPv4-only), but still apply the in-process deny. Logged at `Warn`.
- Fire-and-forget UDP write. On send error log at `Warn` and carry on — emitter failure must never block the accept loop or the login flow.

### `@rename` and admin-menu Rename

- New `@rename <user> <new>` admin command. Admin-tier only (not builders).
- New "Rename" transition in the M6.4 `adminUserView` state, under Users → individual user.
- Both go through the shared `ValidateNewUsername` helper (syntax → disallowed-list → username-history → DB uniqueness).
- Mail/board/file row snapshots (`mail.from_name`, `mail.to_name`, etc.) are intentionally **not** rewritten — those are FTS-0001 header preservation, not denormalised user data. An old message from "fred" still reads `From: fred` after fred renames to "barney".
- Rename forcibly boots all live sessions for the renamed account via the existing `BootAccount` path so the in-memory `s.account.Username` cannot drift from the DB.

### Username history & reservation

- Every rename writes one row to a new `username_history` table inside the same `DB.Write` transaction as the `UPDATE accounts SET username=…`. The row records `old_username`, `account_id`, `renamed_at`, `renamed_to`, and `renamed_by`.
- A previously-used name is **reserved**: future account-create and rename attempts that target it are rejected with `ErrUsernameReserved`. This keeps old mail / board snapshots ("From: alice") from ever silently referring to a different account.
- Same-account self-rotation is permitted. The validator takes a `forAccount` argument; if the historical row points at the same account doing the rename, the check passes, so an admin can flip `alice → arwen → alice` without permanent self-lockout.
- Repeated rotation on the same name re-uses the history row via `INSERT … ON CONFLICT(old_username) DO UPDATE`, refreshing `renamed_at` / `renamed_to`.
- Admin escape hatch: `@username-history release <oldname>` (and matching menu / Lua entry points) deletes the row, freeing the name for re-use. Audited like any other admin mutation.

## Out of scope

- Self-service rename. The validator is shared, but M6.6 only wires admin entry points.
- Per-account login-attempt counters. The counter is per-IP only.
- A general connection cap. The accept loop remains unbounded for unflagged IPs; that fight is M7's. M6.6 makes flagged-IP rejection cheap but does not throttle clean traffic.
- Permanent UDP-flag retry / queue. The wire is best-effort; subtext-filter's restart-rehydrate covers most outages.
- Anything that needs the M7 event bus.

## Architecture

### New package `internal/security`

```
internal/security/
  doc.go
  service.go            // Service: sole writer of cache+DB; central admin-facing API
  usernames.go          // disallowed-name DAO + IsDisallowed(ctx, name)
  history.go            // username_history DAO + IsReserved(ctx, name, forAccount)
  iplist.go             // ip_denials DAO + cache hydration
  iplist_cache.go       // map[netip.Addr]entry + RWMutex + lazy eviction + janitor
  filter.go             // UDP emitter for subtext-filter (IPv4 only)
  attempts.go           // per-IP failed-password sliding-window counter
  service_test.go usernames_test.go history_test.go iplist_test.go iplist_cache_test.go filter_test.go attempts_test.go
```

`Service` is the only writer of both DB rows and cache entries. Every mutation (`AddTempDeny`, `AddPermanentDeny`, `RemoveDeny`, `DisallowUsername`, `AllowUsername`, …) takes the service's own `sync.RWMutex`, calls `DB.Write(...)` inside the locked region, then updates the cache after the write commits. Admin commands, the auto-flag path, and the Lua surface all funnel through these methods — there is no second writer, so the cache and DB cannot drift.

`Flag(ctx, ip, reason)` is the atomic "add to temp deny + emit UDP" operation that the disallowed-username and failed-password triggers both call.

- **Rename into disallowed**: `@rename alice admin` (where `admin` is in the deny list) returns `ErrUsernameDisallowed` and leaves both the account and `username_history` untouched.
- **Self-protection on seed**: pre-create an account `admin`, run migrate. Asserts `disallowed_usernames` does not contain `admin` and that the account still logs in.

## Acceptance criteria

1. A telnet connect that sends `root` (or any seeded name) is disconnected before the password prompt, lands in `ip_denials` with `expires_at = now + auto_deny_ttl_seconds`, and emits one `slog` line with `reason="disallowed_username"`.
2. A subsequent telnet connect from the same source IP is closed at accept-time with no banner or prompt rendered, and emits one `slog` line with `reason="ip_denied"`.
3. Five wrong-password attempts within 60 seconds from one IP cause the sixth to be dropped at accept.
4. With `security.filter.enabled = true` and a reachable subtext-filter (or test stand-in), every flag emits one UDP packet whose payload is exactly the offending IPv4 dotted-quad string with no terminator.
5. `@username-deny add admin` errors out if `accounts.username = 'admin'` exists; otherwise inserts the row. `@username-deny list` paginates. `@username-deny remove` deletes.
6. `@ip-deny add 1.2.3.4 permanent`, `@ip-deny add 1.2.3.5 temp 600`, `@ip-deny list`, `@ip-deny remove 1.2.3.4`, and `@ip-deny flush-temp` all behave per help text.
7. `@rename alice arwen` updates `accounts.username`, writes one `username_history` row inside the same transaction, boots any live session for the account, and refuses if `arwen` is disallowed, reserved, or already taken. Mail snapshots remain on the old name.
8. Creating a new account named `alice` after the rename above returns `ErrUsernameReserved`. After `@username-history release alice`, the create succeeds. `@username-history list alice` shows the row before release and nothing after.
9. The admin-menu "Security" entry shows the disallowed-username list, the reserved-names list, and the IP deny list with full CRUD. The `adminUserView` shows a Rename action and a Show-history action, both running through the shared validator / DAO.
10. The `wintermute.account.*` Lua surface gains `rename`, `username_history`, `release_old_username`; the `wintermute.security.*` Lua surface exposes the seven deny-list methods. Each is verified by an init-script integration test.
11. With `security.auto_deny_enabled = false`, disallowed-username attempts still drop the connection and still emit the structured log line, but **do not** insert into `ip_denials`. The same IP can immediately reconnect (only to be dropped again on the next disallowed name).
12. `make lint check-headers test` is green.

## Risks & open questions

- **No connection cap.** A flagged IP gets cheap rejection, but an unflagged attacker has unlimited goroutines until they trip the failed-password threshold. Caps and global rate-limiting are explicitly M7's responsibility.
- **subtext-filter is unauthenticated.** Anyone who can reach UDP/1234 on the bridge host can blackhole arbitrary IPs. The example config documents this: ship the bridge on a private / management VLAN, or firewall the listener to the Wintermute host. Wintermute itself adds no shared secret because subtext-filter has no field to carry one.
- **subtext-filter TTL is fixed at 5 minutes server-side.** Operators who want Wintermute's local deny to outlive the upstream nft rule must either re-emit periodically (not planned) or fork subtext-filter. Documented; out of scope.
- **Failed-password window is in-memory only.** A bot that paces 4-attempts-per-60s indefinitely never trips the threshold. Acceptable for M6.6; smarter exponential-decay heuristics belong with the M7 event bus where they can be fed by other signal sources.
- **Disallowed-username drop is enumeration-revealing.** Hitting an allowed name prompts for password; hitting a disallowed name drops immediately. An attacker can scrape the deny list with a few thousand probes. Acceptable — the deny list is anti-bot triage, not a secret.
- **Rename mail snapshots.** Preserved as FTS-0001 header data, not denormalised user data. Documented explicitly; an admin who wants to scrub history must do so via Lua.
- **Username-history pool grows monotonically.** Every rename reserves another name forever. Because rename is uncommon and the table is small (one row per rename per name), this is acceptable; the `@username-history release` admin command is the relief valve when an operator really wants a name freed.
