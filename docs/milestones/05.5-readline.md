# Milestone 05.5 — Readline line editing

## Goal

Sessions on ANSI-capable terminals get in-line editing: cursor movement, history (Up/Down), word-level kill, and the usual emacs control bindings (Ctrl-A/E/U/K/W). On non-ANSI terminals (PETSCII, plain ASCII, or anything that fails the M1 capability probe) input continues to behave exactly as it does today. History is per-session and in-memory; no on-disk persistence.

This milestone is a quality-of-life pass that slots between M5 and M6. It does not unlock new player-facing features; it makes every existing prompt (command loop, M5 paste-mode editor, M6 mail/board compose) feel modern when the terminal supports it.

## Dependencies

- M1 (connection layer): uses `term.Capabilities`, the encoder, and the existing `Session.readLine` seam.
- Independent of M2–M5 logically; in practice ships after M5 so paste-mode is in place and we know what the "plain" callers look like.
- Does not block M6.

## Scope

- New package `internal/term/readline`.
- New `ANSI bool` axis on `term.Capabilities`, populated by `AutoDetect` from the existing `DetectHints.ANSICapable`.
- Per-session in-memory history (ring buffer, capped, configurable; default 100 entries).
- Smart-mode entry point used by the command loop; existing simple loop kept for password entry, paste mode, and pre-login phases.
- The following editing operations:
  - Cursor: Left / Right (`\x1B[D` / `\x1B[C`), Home / End (`\x1B[H` / `\x1B[F`), Ctrl-A / Ctrl-E.
  - Edit: Backspace (0x08, 0x7F), Delete (`\x1B[3~`), insert at cursor, Ctrl-W (kill word left), Ctrl-U (kill to start), Ctrl-K (kill to end).
  - History: Up / Down (`\x1B[A` / `\x1B[B`), with the in-progress draft preserved across browsing.
  - Control: Ctrl-C cancels the current line, Ctrl-D on an empty line returns `io.EOF`.

## Out of scope

- Persisted history (per-account, on disk). Reserved for a later QoL pass once player accounts feel stable.
- Tab completion (commands, player names, room slugs). Real value, but a separate design effort — completion needs a source-of-truth registry the world layer doesn't expose today.
- vi mode.
- Reverse-incremental search (Ctrl-R).
- Multi-line input or wrapping editing across `Capabilities.Width` boundaries. Tier 1 assumes the edited line fits on a single screen row; longer lines are best-effort and may display oddly.
- Wide-character / combining-mark cell accounting. Tier 1 assumes one terminal cell per decoded rune.
- A third-party readline library. Existing Go libraries (`chzyer/readline`, `peterh/liner`) assume real stdin/stdout and don't compose with the telnet `Conn` + encoder stack.
- PETSCII cursor editing. PETSCII has its own movement codes; tier 1 falls back to the simple loop for PETSCII sessions.
- The `ed`-style line editor for `@edit` (M5 already deferred this; M5.5 does not address it).

## Architecture

### Packages introduced

- `internal/term/readline` — line editor, key parser, history ring buffer. No dependencies on `internal/session` or the world layer; takes a `*bufio.Reader`, an `io.Writer`, a `term.Capabilities`, and a `*term.Encoder`.

### Capability gate

A new boolean is added to `term.Capabilities`:

```go
// Capabilities (additions)
type Capabilities struct {
    // ... existing fields ...

    // ANSI indicates the terminal understands ANSI CSI sequences for
    // cursor movement, erase-line, and SGR. Set by AutoDetect from the
    // press-enter Device Attributes probe in M1. Independent of Color
    // (some terminals do CSI cursor movement but not color, and vice
    // versa).
    ANSI bool
}
```

`AutoDetect` is updated to set `ANSI = h.ANSICapable`. `ApplyEncodingDefaults` does not touch ANSI — it is an independent axis driven entirely by the live probe.

The dispatcher in `internal/session/session.go` chooses between editors:

```go
// Smart line read, used by the command loop. Falls back to the simple
// loop when the terminal cannot render CSI redraws or when echo is
// suppressed.
func (s *Session) readLineEditing() (string, error) {
    if !s.shouldUseEditor() {
        return s.readLine()
    }
    return readline.ReadLine(s.in, s.writer(), s.caps, s.enc, s.history)
}

func (s *Session) shouldUseEditor() bool {
    return s.caps.ANSI && s.echoOn() &&
        s.enc != nil &&
        s.caps.Encoding != term.EncodingPETSCII
}
```

The existing `readLine()` is unchanged. Callers that want plain behavior (password entry, paste-mode compose, pre-login prompts) continue to call `readLine()` directly; only the command loop in `internal/session/command.go` switches over to `readLineEditing()`.

### Editor

```go
// internal/term/readline/readline.go

package readline

// History captures the in-memory history for one session.
type History struct {
    entries []string
    cap     int
    cursor  int     // -1 means "on the live draft"; 0..len-1 indexes entries
    draft   string  // text typed before the user pressed Up
}

func NewHistory(cap int) *History
func (h *History) Add(line string)
func (h *History) Prev(current string) (string, bool)
func (h *History) Next() (string, bool)
func (h *History) Reset()

// ReadLine reads one line of edited input, drawing prompt/edits to w and
// reading bytes from in. enc is used to decode incoming wire bytes into
// runes (so the cursor operates on user-visible characters, not raw
// bytes).
//
// Returns the finished line on Enter, io.EOF on Ctrl-D over an empty
// buffer, and ErrInterrupt on Ctrl-C.
func ReadLine(in *bufio.Reader, w io.Writer,
    caps term.Capabilities, enc *term.Encoder, hist *History) (string, error)

var ErrInterrupt = errors.New("readline: interrupt")
```

The editor maintains its state as `[]rune` plus an integer cursor index. Every edit follows the same pattern:

1. Mutate `runes` / `cursor`.
2. Move cursor back to the column right after the prompt.
3. Re-emit the line as encoded wire bytes via `enc.EncodeOut`.
4. Emit `\x1B[K` (erase to end of line).
5. Move cursor back to the logical position.

Movement uses `\x1B[<n>D` and `\x1B[<n>C`. The editor does not redraw the prompt; the caller is expected to have printed it before invoking `ReadLine`.

### Key parser

```go
// internal/term/readline/keys.go

type Key int

const (
    KeyChar Key = iota
    KeyEnter
    KeyBackspace
    KeyDelete
    KeyLeft
    KeyRight
    KeyHome
    KeyEnd
    KeyUp
    KeyDown
    KeyKillToEnd     // Ctrl-K
    KeyKillToStart   // Ctrl-U
    KeyKillWord      // Ctrl-W
    KeyInterrupt     // Ctrl-C
    KeyEOF           // Ctrl-D on empty buffer; surfaced separately by editor
    KeyClear         // Ctrl-L (redraw)
    KeyUnknown
)

type Event struct {
    Key  Key
    Rune rune  // valid only when Key == KeyChar
}

// readEvent consumes one logical input event from in. Decodes multibyte
// sequences via enc; CSI sequences are recognized inline. enc may be nil
// for ASCII-only callers.
func readEvent(in *bufio.Reader, enc *term.Encoder) (Event, error)
```

CSI recognition is small enough to hand-roll: on receipt of `\x1B`, peek one byte. If it's `[`, consume digits/`;` until a final byte arrives, then switch on the final byte (`A`/`B`/`C`/`D`, `H`/`F`, `~` with the digit `3`). Anything unrecognized becomes `KeyUnknown` and is discarded.

Plain bytes ≥ `0x20` are routed through the encoder's `DecodeIn`. For UTF-8 sessions a partial multibyte sequence is held in a small staging buffer until either a complete rune arrives or a control byte interrupts; for single-byte encodings (CP437/Latin-1/MacRoman/ASCII) every byte decodes immediately.

### History semantics

- Ring buffer, append-on-Enter, capped at `cap` entries. The newest entry is `entries[len-1]`. When full, the oldest is dropped.
- Empty lines are not added.
- A line identical to the immediately-previous entry is not added (de-dup).
- `Prev` snapshots the current draft on the first call after `Reset`, so the user can walk back into history and then walk forward to retrieve their unfinished line.
- History is owned by `Session` and constructed in `newSession`. Default capacity comes from a new config field `session.history_size` (default 100); set to 0 to disable.

### Concurrency

The world layer can call `Session.writeString` from a foreign goroutine (room broadcasts, NPC speech). `writeMu` already serializes those writes. While `ReadLine` is mid-edit, a broadcast that arrives will print on top of the user's editing line — same as in the current code. Tier 1 accepts this and documents Ctrl-L as the user-driven redraw escape hatch. A proper "broadcast above the prompt" treatment is a later QoL pass.

## Schema changes

None. History is in-memory only.

`wintermute.toml` gets one new field:


Default applied in `internal/config` if the field is absent.

## Acceptance criteria

1. On an ANSI-capable terminal, typing `abcd`, pressing Left twice, then `X` produces `abXcd` with the cursor between `X` and `c`.
2. Pressing Up at the command prompt recalls the previous submitted line; pressing Down returns to the in-progress draft that was held when Up was first pressed.
3. Ctrl-W deletes the word to the left of the cursor (run of non-space characters, plus any trailing whitespace).
4. Ctrl-C cancels the current edit, the server prints `^C\n`, and the command loop reads the next line fresh.
5. On a PETSCII session or any session where the M1 probe yielded `ANSICapable == false`, line input behaves byte-for-byte identically to a pre-M5.5 build (verified by an integration test that drives the dumb path explicitly).
6. Password entry and paste-mode compose are unaffected: arrow keys are not interpreted, the literal bytes flow through `readLine` as before.
7. History is bounded at `session.history_size` entries; identical consecutive entries are de-duplicated; empty lines do not enter the history.
8. Disconnecting and reconnecting yields an empty history (no persistence).
9. All new files carry the MIT SPDX header and pass `make check-headers`.

## Risks & open questions

- **Wide characters and combining marks**: tier 1 assumes one terminal cell per rune. A line containing CJK or combining marks will display correctly but the cursor math will be off by the difference between rune count and cell count. Acceptable for tier 1; if it bites in practice the fix is to route width through `golang.org/x/text/width` or `mattn/go-runewidth`.
- **Long lines exceeding terminal width**: tier 1 does not track wrap. Lines longer than `Capabilities.Width - len(prompt)` will display with cursor-position drift on the second visual row. Document as a known limitation; the proper fix is row-aware redraw, which is a tier-2 concern.
- **Broadcasts mid-edit**: another goroutine writing through `writeString` while `ReadLine` is active will overwrite the editing line. Ctrl-L (redraw) is the user-visible escape hatch. A real fix — buffering broadcasts during edits, or printing them above the prompt — is intentionally deferred.
- **Encoder state during editing**: `DecodeIn` is called per-event. For UTF-8 multibyte input split across `bufio.Reader.ReadByte` calls, the editor holds the partial bytes in a small staging buffer keyed to the current encoding (UTF-8 only; the other encodings are single-byte). Tests must cover the split-multibyte case explicitly.
- **Terminal lying about being ANSI**: if a client sends a DA response but does not actually honor CSI cursor movement, the editor will appear broken with no fallback. Acceptable; the user can hide this behavior via a future `set editor off` preference, but it is out of scope for M5.5.
- **Interaction with the M5 paste-mode editor**: `@edit` calls the plain `readLine` per line of source; no readline behavior is wanted. Confirmed by leaving that call site on `readLine()` rather than `readLineEditing()`.
- **Interaction with M6 mail/board compose**: same as paste mode — plain `readLine`. The M6 plan does not need to change for M5.5 to land.
