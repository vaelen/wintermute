# Milestone 05.7 — Diegetic engagement primitive

## Goal

Players access in-world systems (mail, message boards, file transfer, private NPC dialogue) through *engagement* with diegetic objects rather than top-level commands. Sitting down at a terminal opens a private command interface scoped to that terminal; addressing an NPC by name still works for casual exchanges, but `talk to bartender` opens a focused dialogue session where every line is unambiguously directed at the bartender. Other players in the room see *that* the engagement is happening (`Alice is at the terminal.`) but not its contents.

This milestone introduces the engagement primitive that M6 then plugs into. After M5.7, M6's mail/boards/files functionality lives inside a terminal engagement instead of at the world prompt.

The primitive is designed to also cover player↔player private and semi-private conversation later (bar tables, telepathy), but those flavors are deferred. M5.7 ships only player↔object and player↔NPC engagements.

## Dependencies

- M2 (world layer): rooms, objects, the room subscriber/broadcast model.
- M3 (reactive NPCs): the `internal/npc` registry, per-NPC mutex, and existing `say`-addressed dispatch path. M3's name-tag addressing rule is preserved but becomes engagement-aware.
- M5 (admin scripting): used to expose `wintermute.object.set_engage` to admin Lua. M5.7 does not require player-tier scripting (M8).
- Independent of M5.5 (readline). Strictly speaking, M5.7 builds on M5; it can ship in either order relative to M5.5.

## Scope

- New package `internal/world/engage`: engagement registry, types, built-in handlers, render hooks.
- Session command-loop integration: modal dispatch — while engaged, free input goes to the engagement handler; a small whitelist of meta-commands (`disengage`, `look`, `who`, `help`, plus host-specific disengage verbs) is still parsed by the world parser.
- Two built-in handlers:
  - `terminal` — exposes a command set (the M6 commands; their implementation lands in M6).
  - `npc` — routes free text to the NPC's LLM and writes the reply only to the engaged participant.
- Configurable engage/disengage verbs per host, with universal `engage <target>` / `engage with <target>` / `disengage` fallbacks always available.
- Outside-view broadcasts on engagement open/close, plus inline annotations in the room view from `world.Look` (`Alice (at the terminal)`).
- Engagement-aware M3 fallback: room-level `say` addressing an NPC that's currently engaged with another player produces a one-line brush-off instead of pulling the NPC out of its private conversation.
- Migration `0010_engage.sql` with auto-backfill of `object_engage` rows for existing NPCs, plus a seed terminal in the lobby.
- Admin Lua: `wintermute.object.set_engage(slug, opts)`.
- Seed world: a terminal in the lobby so the feature is reachable on a fresh DB.

## Out of scope

- Player↔player engagements (private dialogue, semi-private joinable conversations). Reserved for a later milestone. The data model is shaped to accommodate >1 participant and a `joinable` policy bit, but neither is exercised here.
- Custom (`kind='custom'`) engagement handlers written in admin Lua. The schema reserves the kind so a later milestone can add Lua-driven handlers without a migration; M5.7 only implements the two built-ins.
- Player-tier scripted engagement handlers (deferred to M8).
- Engagement transcripts / per-player conversation logs. NPC memory (M4) already records short-term and long-term context; persisted user-facing transcripts are a separate feature.
- Idle-timeout auto-disengage. Voluntary, movement-driven, forced (host destroyed), and disconnect-driven closures are the only paths in M5.7.
- NPC autonomy interactions with engagement (M7). M5.7 leaves a forward-dependency note in M7's doc.
- The `terminal` handler's command implementations themselves — those land in M6. M5.7 wires the dispatch but the `mail`/`bb`/`upload`/`download` handlers are stubs returning `not yet implemented` until M6.

## Architecture

### Packages introduced

```
internal/world/engage/
    engage.go      # Engagement, Handler interface, Policy, Registry, Participant
    session.go     # session-side helpers: Open, Close, Route, IsEngaged
    terminal.go    # built-in terminal handler (M6 commands; stubs in M5.7)
    npc.go         # built-in NPC handler (LLM dispatch, M3 brush-off integration)
    verbs.go       # engage-verb / disengage-verb matching helpers
    render.go      # outside-view templating, look-time annotations
```

The world layer gains one hook (`world.Look` consults the registry to annotate participants); no hard dependency from `internal/world` on `internal/world/engage`. The hook is registered at startup, matching the M3 `SayObserver` pattern.

### Core types

```go
// internal/world/engage/engage.go
package engage

type CloseReason int

const (
    CloseVoluntary CloseReason = iota
    CloseMovement
    CloseForced
    CloseDisconnect
)

type Policy struct {
    VisibleActivity bool // is the engagement visible to non-participants?
    AudibleContent  bool // can non-participants hear/see the content?
    Joinable        bool // can non-participants insert themselves?
}

type Host struct {
    ObjectID        world.ObjectID
    Kind            string   // "terminal" | "npc" | "custom"
    EngageVerbs     []string
    DisengageVerbs  []string
    EnterMsg        string   // templated with {{player}}, {{host}}
    PresentMsg      string
    ExitMsg         string
    Prompt          string   // overrides the engagement prompt (terminals)
    Policy          Policy
}

type Handler interface {
    Handle(p *Participant, line string)
    OnOpen(p *Participant)
    OnClose(p *Participant, reason CloseReason)
}

type Engagement struct {
    Host         *Host
    Handler      Handler
    Participants []*Participant   // size-1 in M5.7; set-shaped for the future
}

type Registry struct {
    mu     sync.RWMutex
    byHost map[world.ObjectID]*Engagement
}

func (r *Registry) Open(h *Host, handler Handler, p *Participant) (*Engagement, error)
func (r *Registry) Close(eng *Engagement, reason CloseReason)
func (r *Registry) HostEngagement(id world.ObjectID) *Engagement
func (r *Registry) ParticipantEngagement(sessionID string) *Engagement
```

`Participant` wraps the session with the writer back-channel the handler needs.

For M5.7 the participant set is size-1 (terminal: at most one user; NPC: at most one engaged player). The shape is `[]*Participant` rather than `*Participant` so player↔player engagements can lift this without a type change.

### Session command-loop integration

```go
// pseudocode in the session post-login loop
var defaultMetaCommands = []string{"disengage", "look", "who", "help"}

for {
    line := readLine()
    if eng := s.engagement; eng != nil {
        whitelist := defaultMetaCommands
        whitelist = append(whitelist, eng.Host.DisengageVerbs...)
        first := firstTokenOrFullLine(line)
        if slices.Contains(whitelist, first) {
            // routed to the world parser; "disengage" and host-specific
            // disengage verbs are handled there
            worldParse(s, line)
            continue
        }
        eng.Handler.Handle(s.participant, line)
        continue
    }
    worldParse(s, line)
}
```

A movement attempt (`n`, `s`, `e`, `w`, `u`, `d`, `go <dir>`) inside `worldParse` checks for an active engagement and auto-closes it (`engage.Close(s, CloseMovement)`) before running the move. If the move then fails (e.g. no exit), the engagement is still closed.

### Engage-verb parsing

The world parser, when the standard command table fails to match, consults the engage registry:

```go
// internal/world/engage/verbs.go
func MatchEngageCommand(line string, candidates []*Host, room *world.Room) (host *Host, ok bool)
```

`candidates` is the union of objects in the player's room and the player's inventory that have an `object_engage` row. The matcher tries each host's `engage_verbs` (plus the universal `engage` / `engage with`) as a prefix of the input line; on a match it strips the prefix and runs the remainder through the M3 tiered object matcher (slug → exact → whole-name CI → whole-word token → token-prefix) against `candidates`. Matching is O(objects-in-room × verbs-per-host) per unparsed command, which is fine at MUSH scale.

Ambiguity (`talk to bartender` with two bartenders in the room) surfaces as an `*AmbiguousMatchError` exactly like M3.

### Outside view

Three room broadcasts:

1. **Open** — `enterMsg`, broadcast to the host's room with `excluding = nil` (the engaging participant sees it too as confirmation).
2. **Close** — `exitMsg`, same broadcast rules.
3. **Look-time annotation** — `world.Look` consults `Registry.ParticipantEngagement` for each player listed in the room render and appends `(at the terminal)` / `(talking with the bartender)` / etc., formatted from the host's `present_msg`. Implemented in `internal/world/render` via a hook function set at startup.

No periodic "still engaged" tick. The look annotation is enough.


The prompt rendering uses `host.Prompt` if set, else `terminal>`. The handler's `OnOpen` writes the prompt; `OnClose` does nothing visible (the room sees the `exitMsg`).

### NPC handler

```go
// internal/world/engage/npc.go
type NPCHandler struct {
    host *Host
    npc  *npc.NPC
}

func (h *NPCHandler) Handle(p *Participant, line string) {
    // acquire npc.mu, build chat context (persona + private-conversation note
    // + rolling short-window of engagement turns), call llm.Chat, write reply
    // only to p.session.
}
```

System-prompt addition for an engaged NPC:

> You are in a private conversation with `<participant display name>`. They are speaking directly and only to you. Other people in the room may be visible to you but cannot hear what you are saying.

The per-engagement turn buffer is in-memory and discarded on close. M4 summarization is wired into `OnClose` (one-shot summarize+embed of the conversation) in M4's own milestone — M5.7 leaves a stub.

### M3 fallback engagement-awareness

`internal/npc.HandleSay` is modified:

```go
if eng := engageRegistry.HostEngagement(npc.ObjectID); eng != nil {
    if !eng.HasParticipant(speakerSessID) {
        // the engaged NPC is being addressed by name from outside the engagement
        world.Broadcast(roomID, nil, fmt.Sprintf(
            "%s raises a finger to %s — \"one moment.\"",
            npc.DisplayName, speakerName))
        return
    }
    // engaged speaker shouldn't reach this path; ignore silently
    return
}
// existing M3 addressing logic continues
```

The brush-off string is hardcoded in M5.7. Making it configurable per-NPC is a small follow-up.

### Lifecycle

| Trigger | Reason | Outside view | Notes |
|---|---|---|---|
| `disengage` or a host disengage verb | `CloseVoluntary` | yes (`exitMsg`) | normal path |
| Movement (`n`, `go north`, etc.) | `CloseMovement` | yes | runs before the move; engagement closes even if move fails |
| Host destroyed or admin force | `CloseForced` | yes (`The terminal flickers and dies.` or `exitMsg`) | rare |
| Disconnect | `CloseDisconnect` | yes (`exitMsg`); player additionally falls asleep | runs in the session-cleanup path |

A player can be in at most one engagement at a time. A second `use <something>` while already engaged produces `You're already at the terminal.` (parameterized on host display name).

Engagements with the **host** also have capacity 1 in M5.7: a second player attempting `use terminal` while the terminal is occupied gets `The terminal is in use.`; a second player attempting `talk to bartender` while the bartender is engaged gets `The bartender is occupied.`

## Schema changes

`internal/store/migrations/0010_engage.sql` (single combined migration: table, NPC backfill, and the seed terminal placed in the lobby):

```sql
-- Copyright (c) 2026 Andrew C. Young <andrew@vaelen.org>
-- SPDX-License-Identifier: MIT

CREATE TABLE object_engage (
    object_id        INTEGER PRIMARY KEY REFERENCES objects(id) ON DELETE CASCADE,
    kind             TEXT NOT NULL CHECK (kind IN ('terminal','npc','custom')),
    engage_verbs     TEXT NOT NULL DEFAULT '[]',  -- JSON array of verb strings
    disengage_verbs  TEXT NOT NULL DEFAULT '[]',  -- JSON array of verb strings
    enter_msg        TEXT,                        -- nullable; templated with {{player}}, {{host}}
    present_msg      TEXT,                        -- shown in `look` annotation
    exit_msg         TEXT,                        -- shown on close
    prompt           TEXT,                        -- override for the in-engagement prompt
    policy           TEXT NOT NULL DEFAULT '{}'   -- JSON {visibleActivity, audibleContent, joinable}
);

-- backfill: every existing kind='npc' object gets an engage row with
-- kind='npc' and empty overrides (defaults apply at runtime).
INSERT INTO object_engage (object_id, kind)
SELECT id, 'npc' FROM objects WHERE kind = 'npc';

-- seed: a terminal object in the lobby so the feature is reachable on a fresh DB.
-- (Coordinate slug/name with M2's seed.)
```

The seed-terminal `INSERT` statements (one row in `objects`, one in `object_locations`, one in `object_engage`) live at the end of the same migration file.

Kind-defaults applied in code (not SQL):

| kind     | engage_verbs           | disengage_verbs            | enter_msg                                  | exit_msg                                    | prompt        |
|----------|------------------------|----------------------------|--------------------------------------------|---------------------------------------------|---------------|
| npc      | `talk to`, `address`   | `leave`, `goodbye`         | `{{player}} turns to {{host}}.`            | `{{player}} turns away from {{host}}.`      | (none)        |
| terminal | `use`, `sit at`        | `stand up`, `step away`    | `{{player}} sits down at {{host}}.`        | `{{player}} steps away from {{host}}.`      | `terminal> `  |
| custom   | (must be set)          | (must be set)              | (must be set)                              | (must be set)                               | (must be set) |

A row in `object_engage` with empty JSON arrays / NULL message fields inherits the kind-default. An explicit non-empty array *replaces* the default; an explicit non-NULL string *overrides* the default.

## Admin Lua surface

```lua
-- Mark an existing object as engageable. Overrides default kind-verbs/messages
-- field-by-field; pass nil to keep a default.
wintermute.object.set_engage(slug, {
    kind = "terminal",
    engage_verbs    = { "sit at", "use", "boot up" },
    disengage_verbs = { "stand up", "log off" },
    enter_msg       = "{{player}} drops into the chair and the comlink screen flickers on.",
    exit_msg        = "{{player}} logs off the comlink.",
    prompt          = "comlink> ",
})

-- Remove engageability:
wintermute.object.clear_engage(slug)
```

Custom-kind handlers (Lua-authored) are reserved at the schema level (`kind='custom'`) but not implemented in M5.7. Attempting `kind = "custom"` in `set_engage` returns `not yet implemented`.

## Acceptance criteria

1. A player can `use terminal` and `talk to bartender` in the seed world; both open private engagements.
2. While Alice is engaged with the terminal, free text she types goes to the terminal handler; `say` from other room occupants still reaches her; her terminal commands are invisible to others.
3. `look` from a third party in the room shows engaged players with the engagement annotation (`Alice (at the terminal)`).
4. Default engage verbs `engage <target>` / `engage with <target>` and default disengage `disengage` work for every engageable host even without per-host overrides.
5. Per-host `engage_verbs` / `disengage_verbs` configured via admin Lua work and persist across restarts.
6. While the bartender is in a private engagement with Carol, David's `say hi bartender` produces the brush-off (`The bartender raises a finger to David — "one moment."`) and Carol's conversation is uninterrupted.
7. A movement command auto-disengages cleanly: the room sees the `exitMsg`, then the movement broadcast.
8. Two players cannot occupy the same terminal or the same NPC engagement simultaneously.
9. The terminal command table is present and dispatches to stubs that return `not yet implemented (M6)` for every M6 command. (M6 fleshes these out; M5.7's job is the dispatch infrastructure.)
10. All new source files carry the MIT header.

## Risks & open questions

- **Player↔player engagements**: the data model accommodates multi-participant + joinable, but actually implementing player invitations, semi-private joinability ("Bob approaches Alice and Carol's table"), and audible-but-private speech is a larger UX problem than it looks. Deferred deliberately; design notes in this milestone should age well.
- **Engagement-aware NPC autonomy (M7)**: an autonomous NPC that is in a private engagement should suppress its room-level ambient chatter (or at least handle the case where it has been chattering and is now engaged). Add a forward-dependency note to M7's milestone doc.
- **Multi-participant terminals** (two characters crowding the same comlink). Accommodated in the data shape but not exposed; revisit when there's a concrete need.
- **Engagement transcripts**: should engagement content be persisted as a per-player "conversations" log? Not in M5.7. M4's NPC long-term memory captures the NPC side; a user-facing transcript is a separate feature.
- **Brush-off configurability**: M5.7 hardcodes the brush-off string. Per-NPC override is a trivial follow-up; flagged here so we don't pretend it's already configurable.
- **Engage-verb parser cost**: O(objects × verbs) per unparsed command. Fine at MUSH scale, but if a single room ever has hundreds of engageable objects, the matcher becomes the slow path. Mitigation deferred — measure when it matters.
- **`look` while engaged**: M5.7 routes `look` through the world parser (meta-command whitelist), showing the room. A handler may someday want a custom `look` (e.g. a terminal screen state). Leaving this as future flexibility — the handler can add commands like `screen` instead, no design change required.
- **Inventory-hosted hosts and movement**: a player carrying a pocket comlink can engage it inside a room. Movement auto-disengages, then the player carries the comlink with them. This is the desired behavior; flag it so reviewers aren't surprised.
