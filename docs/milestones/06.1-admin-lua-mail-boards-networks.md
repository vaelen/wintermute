# Milestone 06.1 — Admin Lua APIs for mail, boards, and FTN networks

## Goal

Expose the M6 mail, boards, and ftn-networks subsystems to the M5 admin-Lua surface so that operators can seed boards, broadcast system mail, and inspect / re-flag network rows from `init.*` scripts and live `@`-commands — without dropping into raw SQL. No new in-game admin commands ship in this milestone; only the Lua API.

## Dependencies

- M6 (mail/boards/files services exist and are wired into `cmd/wintermute`).
- M5 (admin-Lua VM, world API surface, tool registry).

## Scope

### `wintermute.board.*`

- `wintermute.board.create({ slug, name, description?, network?, area_tag?, read_min_level?, post_min_level?, admin_min_level? })` → board id. `network` defaults to `"local"`. ACL levels default to `player`/`player`/`admin`.
- `wintermute.board.delete(slug)` — refuses if posts exist (matches `boards.Service.DeleteBoard`).
- `wintermute.board.get(slug)` → table mirroring `boards.Board`.
- `wintermute.board.list()` → array of board tables (admin sees all networks; no read-ACL filtering at this surface).
- `wintermute.board.set_acls(slug, { read?, post?, admin? })` — updates the per-board level bands without touching other fields.

### `wintermute.mail.*`

- `wintermute.mail.send_from_system(to_username, subject, body, opts?)` → mail id. Sender appears as a configurable system handle (default `"system"`); the underlying row stores `from_id = NULL` and `from_name = "<system>"`. Adds a new `Service.SendFromSystem` method so the existing `Send(*auth.Account, …)` signature stays nil-unsafe.
- `wintermute.mail.broadcast(subject, body, opts?)` — sends the same message from `<system>` to every account matching `opts.access_level` (default: all). Returns the count delivered.
- `wintermute.mail.delete_for_user(username, mail_id)` — admin override for purging individual messages.
- `wintermute.mail.unread_count(username)` → integer.

### `wintermute.ftn.network.*`

- `wintermute.ftn.network.list()` → array of `{ slug, name, domain, our_addr, is_default }`.
- `wintermute.ftn.network.get(slug)` → single network table.
- `wintermute.ftn.network.set_default(slug)` — clears the current default and sets the named one (within a single writer-tx so the partial unique index isn't tripped). The configured TOML still owns the *list* of networks; this just lets a script swap defaults at runtime.

`wintermute.ftn.network.add` / `.delete` are deliberately **not** exposed — adding or removing a network is a config-file operation (operator intent: edit `wintermute.toml`, restart), because changing origaddr after MSGIDs have been issued invalidates the FTS-0009 uniqueness contract for previously-issued serials.

## Out of scope

- Any new in-game `@`-commands wrapping these APIs — that lands in a later admin-UI milestone.
- File-administration Lua APIs (deferred to M6.2).
- Player-tier sandboxed scripts touching mail/boards (M8 will inherit a tightly ACL-scoped subset).

## Architecture

`internal/world/api` already holds the admin API struct. M6.1 adds three new sets of binding methods, each on its own file:

- `internal/world/api/mail.go` — wraps `*mail.Service`.
- `internal/world/api/boards.go` — wraps `*boards.Service`.
- `internal/world/api/ftn.go` — wraps `*ftnnetworks` package-level functions.

`internal/script/lua/api.go` registers each as a sub-table on the global `wintermute` table at VM construction. The wiring follows the same closure-capture pattern used by `wintermute.object.set_engage` / `clear_engage` today.

`internal/mail` grows a small `SendFromSystem(ctx, toUsername, subject, body)` that doesn't require an `*auth.Account`. The from-name is configurable on the service constructor (`SystemName string`, default `"<system>"`).

## Implementation tasks

1. Add `Service.SendFromSystem` to `internal/mail`; the existing `Send` is unchanged.
2. Add binding methods to `internal/world/api` (mail/boards/ftn).
3. Register the new tables in the Lua VM pool's startup glue.
4. Update `worldapi.API` in `cmd/wintermute/main.go` to receive the new services.
5. Unit tests in `internal/world/api` for each binding.
6. Round-trip tests in `internal/script/lua` that call each new method from a Lua snippet and assert DB state.

## Acceptance criteria

1. An `init.*` script can create three boards (one local, two on different declared FTN networks) with custom ACL bands; all three appear in `wintermute.board.list()`.
2. A script can call `wintermute.mail.broadcast("Welcome", "…")` and every account's inbox grows by one row whose `from_name = "<system>"`, `from_id = NULL`, MSGID stamped with the `local` network's origaddr.
3. A script can call `wintermute.ftn.network.set_default("fidonet")` and the partial unique index remains satisfied; `wintermute.ftn.network.list()` shows fidonet as default and `local` no longer is.
4. All new files carry the MIT header; `make lint check-headers test` is green.

## Risks & open questions

- **System mail and FTN egress**: a `<system>`-from message is local-only. If the FTN gateway lands later and wants to gate a system broadcast as netmail, the gateway needs a real address. For now this is fine; revisit when the gateway milestone is on deck.
- **Broadcast cost**: `wintermute.mail.broadcast` materialises one mail row per account. The MSGID issuer bumps once per row (each is a distinct message, FTS-0009-correct). For very large rosters this is O(n) writes; acceptable at M6's scale.
- **ACL on the Lua surface**: M5 already gates `wintermute.*` to admin-tier scripts. These bindings inherit that gate; no extra checks here.
